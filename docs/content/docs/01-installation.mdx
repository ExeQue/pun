## Standalone installer

Install the latest release to `~/.pun/bin`, without Composer or PHP:

```bash
curl -fsSL https://pun.laravel.cloud/install | sh
```

To install a specific version, pass it to the script:

```bash
curl -fsSL https://pun.laravel.cloud/install | sh -s -- v0.1.1
```

Pun ships binaries for Linux and macOS, on x86_64 and arm64. The Linux binaries are static musl builds, so they run on glibc distributions and on Alpine. On Apple silicon, the installer picks the arm64 binary even in a shell that runs under Rosetta. Windows is not supported.

The installer also puts `punx` beside `pun`. It is the same binary, and `punx` runs [`pun x`](/docs/commands/x).

To update, run [`pun self-update`](/docs/commands/self-update), or run the installer again. To uninstall, delete `~/.pun`. Set `PUN_INSTALL` to install somewhere other than `~/.pun`; the binary goes in `$PUN_INSTALL/bin`.

The installer checks the download before it installs anything:

- It downloads over HTTPS only, with TLS 1.2 or later, including on redirects.
- It checks the archive's SHA-256 checksum.
- When the GitHub CLI is installed and signed in, it checks the archive's GitHub build attestation. The attestation proves that Pun's release workflow built the archive from the release tag. Set `PUN_REQUIRE_ATTESTATION=1` to fail when the attestation cannot be checked.
- It refuses an archive with links or unexpected paths, and a binary that does not report the expected version.
- It never asks for `sudo` and does not edit your shell profile. If `~/.pun/bin` is not on your `PATH`, it prints the line to add.

## Composer

```bash
composer require --dev punphp/pun
vendor/bin/pun --version
```

The package is a small PHP script, and it requires PHP 8.4 or later to run. On first run, it downloads the release binary for its version and platform (Linux or macOS, x86_64 or arm64) from GitHub Releases, checks its SHA-256 checksum, and keeps it in `vendor/bin`. Later runs start that binary directly. Windows is not supported. If the download or the checksum fails, the script exits 2.

To update a Composer install, run `composer update punphp/pun`. `pun self-update` does not replace a Composer install.

These docs write commands as `pun`. In a project, run them as `vendor/bin/pun`, for example `vendor/bin/pun check`, or from a Composer script, where `vendor/bin` is on the `PATH`:

```json composer.json
"scripts": {
    "check": "pun check"
}
```

## Runtime requirements

- Projects must target PHP 8.4 or later. Pun reads the target from `require.php`, in `pun.toml`'s `[require]` or, before [`pun migrate`](/docs/commands/migrate#composer), in `composer.json`. `[php] version` overrides it. A `require.php` that allows PHP below 8.4 stops every check with exit code 2.
- PHP checks need no PHP or Node runtime.
- Blade formatting requires Node.js and these project dependencies. In a project with a `bun.lock` or `bun.lockb` file, Pun runs Prettier with Bun instead of Node.js. Prettier and its plugins are loaded from the project's `node_modules`, so Blade formatting runs project code.

```bash
npm install --save-dev prettier@^3.9.6 prettier-plugin-blade@^3.3.3 prettier-plugin-tailwindcss@^0.8.1
```

- In `*.blade.php` files, Pun does not run `no_unused_imports`, `fully_qualified_strict_types`, `global_namespace_import` or `declare_strict_types`, like Pint. These rules would corrupt the template's PHP blocks.

- Migrating `.php-cs-fixer.php` or `rector.php` requires PHP and the corresponding tool. For Rector, run `composer install` first.
