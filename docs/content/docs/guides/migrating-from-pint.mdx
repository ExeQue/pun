---
title: Migrating from Pint
description: Convert your Pint config, compare the results, and update your scripts and CI.
---

Switch a project from Pint to Pun. Begin with a clean Git working tree, and keep Pint installed until the results match.

<Steps>
  <Step title="Convert the config">

```bash
pun migrate --from pint --dry-run   # preview
pun migrate --from pint
```

Unsupported rules are skipped, with a warning for each.

  </Step>
  <Step title="Compare the results">

```bash
vendor/bin/pint
pun check --fix
vendor/bin/pint --test
pun check
git diff
```

- `vendor/bin/pint --test` and the format part of `pun check` should both pass.
- If they differ, check why before you switch.
- `pun check` can also report lint and analyse problems that Pint doesn't check.

  </Step>
  <Step title="Update scripts and CI">

```json composer.json
{
	"scripts": {
		"lint": "pun check --fix",
		"test:lint": "pun check"
	}
}
```

In CI, replace `vendor/bin/pint --test` with `pun check`. See [CI](/docs/guides/ci).

| Pint | Pun |
| --- | --- |
| `--bail`, `--cache-file` | Not supported |
| `--ansi` / `--no-ansi` | `--color=always` / `--color=never` |
| `txt`, `xml` formats | One of the [other formats](/docs/commands/format#options) |

  </Step>
</Steps>

## What moved where

- Layout rules become format rules.
- Risky and code-deleting rules become lint rules. So `pun format` alone doesn't apply your full Pint config.
- The [Pint mapping](/docs/migrate/from/pint) lists every fixer and its Pun rule.

## Roll back or clean up

Migration keeps `pint.json` and the Pint package.

- To roll back, restore your scripts and CI commands, and check any rewritten ignore comments.
- To remove Pint, run `pun remove laravel/pint` and delete `pint.json`.
