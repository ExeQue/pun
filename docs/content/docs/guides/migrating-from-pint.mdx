---
title: Migrating from Pint
description: Convert your Pint config, compare the results, and update scripts.
---

Start from a clean Git working tree. Keep Pint installed until you have compared the results.

<Steps>
  <Step title="Convert the config">

```bash
pun migrate --from pint --dry-run
pun migrate --from pint
```

Migration skips unsupported rules and warns about each one. Review the warnings.

  </Step>
  <Step title="Compare the results">

```bash
vendor/bin/pint
pun check --fix
vendor/bin/pint --test
pun check
git diff
```

Investigate any difference before you switch. `pun check` can also report lint and analysis findings that Pint does not check.

  </Step>
  <Step title="Update scripts and CI">

```json composer.json
{
	"scripts": {
		"lint": "pun check --fix",
		"test:lint": "pun check"
	}
}
```

In CI, replace `vendor/bin/pint --test` with `pun check`. See the [CI guide](/docs/guides/ci).

  </Step>
</Steps>

## What moved where

Layout rules become format rules. Risky and code-deleting rules become lint rules, so `pun format` alone does not apply your full Pint config. The [Pint mapping](/docs/migrate/from/pint) lists every fixer and its Pun rule.

Migration keeps `pint.json` and the Pint dependency. To roll back, restore your scripts and CI commands, and review any rewritten ignore comments.
