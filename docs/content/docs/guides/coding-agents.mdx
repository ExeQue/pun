When a coding agent runs Pun, the output is short plain text: one summary line, then one line per problem.

```
pun check: fail, 1 error, 2 files with fixes (412 checked, 0.21s)
app/A.php format/arrays/syntax, format/tags/blank-line-after-opening
app/B.php lint/style/no-alias-function [fix:unsafe] Master functions shall be used instead of aliases.
app/D.php:2 syntax-error Parse error: syntax error, unexpected token ";" on line 2.
```

- No color, progress bar or boxes.
- Paths are relative to the project.
- A clean run prints only the summary.
- Lists stop at 20 items. `-v` shows all items and diffs.
- Exit codes are the same as normal output.
- `pun config` and `pun list-files` print their summary on stderr, so stdout stays plain TOML or one path per line.

## Detection

Pun detects agents such as Claude Code, Cursor and Codex from the environment variables they set.

- A missing terminal does not turn agent mode on.
- `CURSOR_AGENT` turns it on. `CURSOR_TRACE_ID` alone does not.

## Overrides

Highest priority first:

| Override | Effect |
| --- | --- |
| `--agent` / `--no-agent` | Agent output on or off for this run |
| `PUN_AGENT=1` / `PUN_AGENT=0` | Same, from the environment |
| `PAO_FORCE=1` / `PAO_DISABLE=1` | Agent mode on or off. `PAO_DISABLE` wins if both are set |

## Machine reports

`--format` replaces agent output. For `format`, `lint` and `check`:

- `--format=json` prints PHP-CS-Fixer's JSON report.
- `--format=agent` prints Pint's JSON agent report.

Neither is the plain-text agent output above.

## Laravel Boost

The `punphp/pun` package ships a [Laravel Boost](https://github.com/laravel/boost) guideline and a `pun-development` skill.

- They have the agent run `pun check --fix --dirty` after it edits PHP files.
- They have it use Pun's package commands instead of Composer's.
- `php artisan boost:install` offers them when `composer.lock` lists `punphp/pun` as a direct dependency.
