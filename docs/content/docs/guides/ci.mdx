In CI, run [`pun check`](/docs/commands/check) without `--fix`. It reports problems and changes nothing.

| Exit code | Meaning |
| --- | --- |
| `0` | No problems |
| `1` | Problems found |
| `2` | Pun could not run |

Warnings fail the run only with `--deny-warnings`, or when there are more than `--max-warnings`.

## GitHub Actions

With Pun in `require-dev`, `composer install` (or `pun install`) puts it in `vendor/bin`. Add a step after the install:

```yaml .github/workflows/style.yml
- name: Check
  run: vendor/bin/pun check
```

- On GitHub Actions, Pun adds annotations to its normal output.
- `--format=github` prints only the annotations.

## Report files

```bash
pun format --test --output-to-file=pun.xml --output-format=checkstyle
```

- `--output-format` takes `checkstyle`, `junit`, `gitlab`, `json`, `agent` or `github`.
- `--format` sets what Pun prints on stdout.

## Pre-commit hook

```bash
pun check --staged
```

`--staged` checks files with staged changes. Pun reads the file on disk, so unstaged edits are checked too.
