---
title: pun format
description: Format PHP layout, casing, and spelling.
---

`pun format` applies the `[format]` rules in `pun.toml`. It changes layout only. Pint's risky and code-deleting fixers are [`pun lint`](/docs/commands/lint) rules, and [`pun check --fix`](/docs/commands/check) runs both.

```bash
pun format
pun format --test
pun format app/Models
```

## Pint's flags

| Flag | What it does |
| --- | --- |
| `--test` (`--check`) | Report files that need formatting without changing them. Exit 1 if any do. |
| `--repair` | Format the files, and exit 1 if any file changed. |
| `--dirty` | Select only files with uncommitted changes. |
| `--diff=<branch>` | Select only files changed since you branched from `<branch>`. |
| `--config=<path>` | Use this `pun.toml`. |
| `--preset=<name>` | Use `laravel`, `psr12`, or `empty` instead of `pun.toml`. For `per`, run `pun migrate --preset per`. |
| `--no-config` | Use the `laravel` preset and no config file. |
| `--format=<fmt>` | `json`, `agent`, `checkstyle`, `junit`, `gitlab`, or `github`. |
| `--output-to-file=<path>` | Also write a report to this file, in the format that `--output-format=<fmt>` names. |
| `--stdin-filename=<path>` | The path of code read from stdin. Pass `-` as the path argument to read stdin. |
| `-v` | Add unchanged files and diffs. |
| `-q` | Print only Pint's stderr line for each changed file. With `--format` or under a coding agent, print nothing, as Pint does. |
| `--max-processes=N` | Cap threads and Prettier workers. `N` is a positive number. Default: one per core. |

## Pun's own flags

| Flag | What it does |
| --- | --- |
| `--staged` | Select only files with staged changes. Pun reads the working tree, not the index. |
| `--watch` | Keep running and format files again as they change. |
| `--explain` | Print the fixers the run applies, in priority order, on stderr. |
| `--no-cache` | Check every file. Don't read or write the [result cache](#cache). |
| `--color=auto\|always\|never` | Color mode. `auto` respects `NO_COLOR`. `always` and `never` also apply to the `--format` reports, as Pint's `--ansi` and `--no-ansi` do. |

## Cache

Pun remembers each file's result, including its findings. The next run reuses that result while the file's content, the config, the flags, and the Pun binary stay the same. Pun checks a file again on the next run after `--fix` changes it.

The cache is one file per project in `$PUN_CACHE_DIR/results`. `PUN_CACHE_DIR` defaults to `~/.cache/pun` (or `$XDG_CACHE_HOME/pun`) on Linux and `~/Library/Caches/pun` on macOS. `--no-cache` or `PUN_NO_CACHE=1` turns the cache off. Code from stdin never uses it. You can delete the file at any time.

To format Blade files, turn on the `laravel/blade` rule in `pun.toml`:

```toml
[format.rules]
"laravel/blade" = true
```

Pun has no `--blade` flag. `pun migrate` turns the rule on when `pint.json` does.

Blade formatting keeps its Prettier worker scripts and Node's compile cache in `$PUN_CACHE_DIR/blade-*`, so later runs start faster. A `NODE_COMPILE_CACHE` that you set yourself takes precedence.

Some lint results use other files, such as a parent class. Those results also depend on every file in the project and on `vendor/composer/installed.json`. A change to any of them makes lint check those files again.

## Output

```
$ pun format
 ✔ app/Http/Kernel.php        format/whitespace/no-trailing
 ✔ app/Models/User.php        format/imports/ordered
Formatted 2 files, 482 unchanged · 484 files in 0.21s
```

`--format=agent` is Pint's JSON reporter, not Pun's [coding-agent output](/docs/guides/coding-agents).

## Exit codes

| Code | When |
| --- | --- |
| 0 | No changes needed, or all changes applied |
| 1 | A file needs formatting with `--test`, a file changed with `--repair`, or a syntax error |
| 2 | Pun could not run: invalid config, unsupported rule, unreadable file, report error, or missing Blade dependency |

Pun prints a run error and a hint on stderr. With `--format` or `-q`, it prints Pint's error box on stdout instead.

## GitHub Actions

When `GITHUB_ACTIONS=true`, the output includes an annotation for each file that needs formatting. `--format=github` prints only the annotations:

```
::error file=app/Models/User.php,line=12,col=0,title=format/arrays/syntax::File needs formatting
::error file=app/Broken.php,line=3,col=1,title=syntax-error::Unclosed '(' on line 2
```

A run error prints `::error ::<message>`.

## Configuration errors

Without `pun.toml`, format exits 2. Run `pun init` or `pun migrate` to create the file, or pass `--preset` or `--no-config`.

A rule that Pun doesn't implement is a configuration error. Pun names the rule and exits 2 before it edits any file.

To apply code fixes as well, see [`pun lint`](/docs/commands/lint).
