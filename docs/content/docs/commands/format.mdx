---
title: pun format
description: Format PHP layout, casing, and spelling.
---

`pun format` applies the `[format]` rules in `pun.toml`. Risky and code-deleting fixers are [`pun lint`](/docs/commands/lint) rules. [`pun check --fix`](/docs/commands/check) runs both.

```bash
pun format
pun format --test
pun format app/Models
```

## Pint's flags

| Flag | What it does |
| --- | --- |
| `--test` (`--check`) | Report style errors without fixing them. Exit 1 on any. |
| `--bail` | Like `--test`, but stop at the first error. |
| `--repair` | Fix errors, and exit 1 if anything changed. |
| `--dirty` | Only files with uncommitted changes. |
| `--diff=<branch>` | Only files changed since branching off `<branch>`. |
| `--blade` | Also format Blade files. |
| `--config=<path>` | Use this `pun.toml`. |
| `--preset=<name>` | Use `laravel`, `psr12`, or `empty` instead of `pun.toml`. For `per` or `symfony`, run `pun migrate --preset <name>`. |
| `--no-config` | Use the `laravel` preset and no config file. |
| `--format=<fmt>` | `json`, `txt`, `agent`, `checkstyle`, `junit`, `xml`, `gitlab`, or `github`. |
| `--output-to-file=<path>` | Also write a report to a file, in `--output-format=<fmt>`. |
| `--stdin-filename=<path>` | Path for code read from stdin (`-` as the path). |
| `-v`, `-q` | `-v` adds unchanged files and diffs. `-q` hides successful output. |
| `--max-processes=N` | Cap threads and Prettier workers. Default: one per core. Invalid or nonpositive values keep the default. |
| `--cache-file=<path>` | Keep the [result cache](#cache) in this file. |

## Pun's own flags

| Flag | What it does |
| --- | --- |
| `--staged` | Only files with staged changes. Reads the working tree, not the index. |
| `--since=<ref>` | Only files changed since a commit, plus untracked files. |
| `--watch` | Keep running and re-format files as they change. |
| `--stdin` | Read code from stdin. `--stdin-filename` gives it a path for exclusions. |
| `--explain` | Print the fixers the run applies, in priority order. |
| `--no-cache` | Check every file. Don't read or write the [result cache](#cache). |
| `--color=auto\|always\|never` | Color mode. `auto` respects `NO_COLOR`. `--ansi` and `--no-ansi` also work. |

## Cache

Pun remembers each file's result, including its findings. The next run reuses the result while the file's content, the config, the flags, and the Pun binary stay the same. A file that `--fix` just changed is checked again on the next run.

The cache is one file per project in `$PUN_CACHE_DIR/results`. The default cache is `~/.cache/pun` (or `$XDG_CACHE_HOME/pun`) on Linux and `~/Library/Caches/pun` on macOS. `--no-cache` or `PUN_NO_CACHE=1` turns it off. Code from stdin never uses it. Deleting the file is safe.

Lint results that use other files, such as a parent class, also depend on every file in the project and on `vendor/composer/installed.json`. A change to any of them makes lint check those files again.

## Output

```
$ pun format
 ✔ app/Http/Kernel.php        format/whitespace/no-trailing
 ✔ app/Models/User.php        format/imports/ordered
Formatted 2 files, 482 unchanged · 484 files in 0.21s
```

`--format=agent` is Pint's JSON reporter, not Pun's [coding-agent output](/docs/guides/coding-agents).

## Exit codes

| Code | When |
| --- | --- |
| 0 | No changes needed, or all changes applied |
| 1 | Formatting changes in test or repair mode, or a syntax error |
| 2 | Pun could not run: invalid config, unsupported rule, unreadable file, report error, or missing Blade dependency |

Pun prints a run error with a hint on stderr. With `--format` or `-q`, it prints Pint's error box on stdout.

## GitHub Actions

Under `GITHUB_ACTIONS=true`, the output includes an annotation for each file that needs formatting. `--format=github` prints only annotations:

```
::error file=app/Models/User.php,line=12,col=0,title=format/arrays/syntax::File needs formatting
::error file=app/Broken.php,line=3,col=1,title=syntax-error::Unclosed '(' on line 2
```

A run error prints `::error ::<message>`.

## Configuration errors

Without `pun.toml`, run `pun init` or `pun migrate`, or pass `--preset` or `--no-config`.

A rule that Pun doesn't implement is a configuration error. Pun names the rule and exits 2 before it edits any file.
