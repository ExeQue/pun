title: pun analyse

---

Find bugs with types, like PHPStan. It never edits files. Also runs as `pun analyze`.

## Usage

```bash
pun analyse [paths] [options]
```

```bash
pun analyse                       # whole project
pun analyse app tests             # some folders
pun analyse --generate-baseline   # accept current errors
```

## Options

| Option | Description |
| --- | --- |
| `--generate-baseline [<file>]` | Save every current error to a baseline and exit 0. |
| `--config <path>` | Use this `pun.toml`. |
| `--format=<fmt>` | Report as `raw`, `json`, `checkstyle`, `junit`, `gitlab`, `github` or `teamcity`. Alias: `--error-format`. |
| `--concise` | One line per error. |
| `--max-processes=<n>` | Limit threads. Default: one per core. |
| `--color=<when>` | `auto`, `always` or `never`. |
| `-v` | Add identifiers to `raw` output. |
| `-q` | Print nothing. The exit code gives the result. |

## What happens

- Reads the `[analyse]` preset and rules from `pun.toml`.
- Checks the files in `[analyse] paths`, or `[files] paths`, or the whole project.
- Reads `vendor/` for classes and functions, but never reports on it.
- Hides errors listed in the baseline (`[analyse] baseline`).
- With the `laravel` extension on, also runs Larastan's checks.
- If a file has a syntax error, reports only syntax errors.

```toml pun.toml
[analyse]
preset = "strict"
paths = ["app", "tests"]
baseline = "pun-baseline.toml"

[analyse.rules]
"types/missing-return-type" = "off"
```

To ignore one line, add `// @pun-ignore <rule> -- <reason>`. See [ignore comments](/docs/configuration/ignore-comments). The [rule reference](/docs/rules/analyse) lists every check.

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | No errors. |
| 1 | Errors. |
| 2 | Pun could not run, or every rule is off. |
