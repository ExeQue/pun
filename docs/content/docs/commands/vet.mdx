---
title: pun vet
description: Check that someone you trust reviewed every locked package, or that you exempted it.
---

```bash
pun vet init
pun vet
pun vet diff monolog/monolog 3.8.0 3.9.0
pun vet certify monolog/monolog 3.8.0 3.9.0
```

`pun vet` checks the packages in your lock against a record of code reviews. Every package must be reviewed by you or by someone whose reviews you import, or be exempted. A dependency update then can't bring in code nobody read: the new version fails the check until someone reviews what changed.

A review is called an audit. It covers either one version of a package or the changes from one version to another. A version passes when a chain of audits leads to it from a full audit or an exemption. For example, a full audit of 1.0.0 plus audits of the changes 1.0.0 → 1.1.0 and 1.1.0 → 1.2.0 cover 1.2.0. Reviewing a diff is usually much less work than reading a whole package.

## Criteria

Each audit and exemption vouches for one criterion:

| Criterion | Means | Needed by |
| --- | --- | --- |
| `safe-to-run` | Safe to run on a developer's machine and in CI | `require-dev` packages |
| `safe-to-deploy` | Safe to run in production. Implies `safe-to-run`. | `require` packages |

Path packages are your own code and metapackages hold no code, so neither needs an audit.

## Start

`pun vet init` creates `supply-chain/` and exempts every locked package at its locked version. The check passes from the start, and every later change to the lock needs an audit. Replace the exemptions with audits over time. Commit `supply-chain/` with the lock.

## When a package fails the check

`pun vet` lists each package that no chain of audits covers, with the command that shows what to review:

```text
✖ 1 of 214 packages is not vetted:

  monolog/monolog 3.9.0 needs safe-to-deploy
    review it: pun vet diff monolog/monolog 3.8.0 3.9.0
```

1. Run the command. `pun vet diff <package> <from> <to>` shows the changes between two versions with `git diff`. When no version of the package is reviewed yet, the command is `pun vet inspect <package> <version>`, which unpacks the version into Pun's cache and prints the directory.
2. Read the code with the criterion in mind.
3. Record the audit with `pun vet certify <package> <from> <to>`, or `pun vet certify <package> <version>` for a full audit. The audit goes in `supply-chain/audits.toml`, with your name from git's `user.name` and `user.email`.

`certify` takes `--criteria`, `--who`, and `--notes`. Without `--criteria`, the audit vouches for what the lock needs of the package.

Versions not in the lock come from Packagist. A branch version names its commit, as in `dev-main#0123abcd`, because a branch moves.

## Import other teams' audits

To trust another team's audits, list their `audits.toml` in `supply-chain/config.toml`:

```toml
[imports.acme]
url = "https://example.com/supply-chain/audits.toml"
```

The URL must use HTTPS. A path such as `../../shared/audits.toml` is read from `supply-chain/`. Pun fetches each import once and keeps the audits of your locked packages in `supply-chain/imports.lock`, so later checks run offline and an import changes only when you run `pun vet fetch-imports`.

## Files

| File | Holds |
| --- | --- |
| `supply-chain/audits.toml` | Your audits |
| `supply-chain/config.toml` | The exemptions and the imports |
| `supply-chain/imports.lock` | The imported audits, as last fetched |

An audit has `criteria`, `who`, optional `notes`, and either `version` or `delta = "<from> -> <to>"`:

```toml
[[audits."monolog/monolog"]]
who = "Ada Lovelace <ada@example.com>"
criteria = "safe-to-deploy"
delta = "3.8.0 -> 3.9.0"
```

`pun vet prune` removes the exemptions the lock no longer needs: those of packages you removed, and those that audits now cover.

## Exit codes

| Code | When |
| --- | --- |
| 0 | Every package is vetted |
| 1 | A package is not vetted |
| 2 | No lock or no `supply-chain/`, an invalid file, or a failed download |
