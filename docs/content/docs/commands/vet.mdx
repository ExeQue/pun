---
title: pun vet
description: Check that every locked package was reviewed or exempted.
---

```bash
pun vet init
pun vet
pun vet diff monolog/monolog 3.8.0 3.9.0
pun vet certify monolog/monolog 3.8.0 3.9.0
```

`pun vet` checks that every locked package was reviewed, by you or a team you import, or exempted. A new version fails until someone reviews what changed.

A review is an audit of one version or of the changes between two. A version passes when a chain of audits reaches it from a full audit or an exemption. For example, audits of 1.0.0, 1.0.0 → 1.1.0, and 1.1.0 → 1.2.0 cover 1.2.0.

## Criteria

| Criterion | Means | Needed by |
| --- | --- | --- |
| `safe-to-run` | Safe on a developer's machine and in CI | `require-dev` packages |
| `safe-to-deploy` | Safe in production. Implies `safe-to-run`. | `require` packages |

Path packages and metapackages need no audit.

## Start

`pun vet init` creates `supply-chain/` and exempts every locked package at its locked version. Commit `supply-chain/` with the lock.

## When a package fails the check

`pun vet` prints the command to review each failing package:

```text
✖ 1 of 214 packages is not vetted:

  monolog/monolog 3.9.0 needs safe-to-deploy
    review it: pun vet diff monolog/monolog 3.8.0 3.9.0
```

1. Run the command. `pun vet diff <package> <from> <to>` shows the changes with `git diff`. For a package with no reviewed version, `pun vet inspect <package> <version>` unpacks it into Pun's cache and prints the directory.
2. Read the code.
3. Run `pun vet certify <package> <from> <to>`, or `pun vet certify <package> <version>` for a full audit.

`certify` writes to `supply-chain/audits.toml` and takes `--criteria`, `--who`, and `--notes`. `--criteria` defaults to what the lock needs. `--who` defaults to git's `user.name` and `user.email`.

Versions not in the lock come from Packagist. Name a branch version with its commit, as in `dev-main#0123abcd`.

## Import other teams' audits

List another team's `audits.toml` in `supply-chain/config.toml`:

```toml
[imports.acme]
url = "https://example.com/supply-chain/audits.toml"
```

The URL must use HTTPS. A relative path is read from `supply-chain/`. Pun stores the fetched audits in `supply-chain/imports.lock`, so later checks run offline. Imports change only when you run `pun vet fetch-imports`.

## Files

| File | Holds |
| --- | --- |
| `supply-chain/audits.toml` | Your audits |
| `supply-chain/config.toml` | The exemptions and the imports |
| `supply-chain/imports.lock` | The imported audits, as last fetched |

An audit has `criteria`, `who`, optional `notes`, and either `version` or `delta`:

```toml
[[audits."monolog/monolog"]]
who = "Ada Lovelace <ada@example.com>"
criteria = "safe-to-deploy"
delta = "3.8.0 -> 3.9.0"
```

`pun vet prune` removes exemptions for removed packages and for versions that audits now cover.

## Exit codes

| Code | When |
| --- | --- |
| 0 | Every package is vetted |
| 1 | A package is not vetted |
| 2 | No lock or no `supply-chain/`, an invalid file, or a failed download |
