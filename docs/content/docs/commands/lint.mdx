---
title: pun lint
description: Find code that could be written better.
---

Find code that could be written better. Use `--fix` to apply the fixes.

## Usage

```bash
pun lint [paths] [options]
```

```bash
pun lint                         # report problems
pun lint --fix                   # apply fixes
pun lint -A lint/style           # turn a group off for this run
pun lint --max-warnings 10       # fail on more than 10 warnings
```

## Options

| Option | Description |
| --- | --- |
| `--fix` | Apply the fixes. Skips rules with `fix = "off"`. |
| `-A`, `--allow <rule>` | Turn a rule or group off. |
| `-W`, `--warn <rule>` | Turn a rule or group on as a warning. |
| `-D`, `--deny <rule>` | Turn a rule or group on as an error. |
| `--deny-warnings` | Fail on any warning. |
| `--max-warnings <n>` | Fail on more than `n` warnings. |
| `--concise` | One line per problem. |
| `--format=<fmt>` | Report as `json`, `checkstyle`, `junit`, `gitlab`, `github` or `agent`. |
| `--no-cache` | Check every file again. |
| `-q` | Print nothing. The exit code gives the result. |

Lint also takes the file options of [`pun format`](/docs/commands/format#options), such as `--dirty`, `--staged` and `--diff`.

## What happens

- Reads the `[lint]` sets and rules from `pun.toml`.
- Checks each file and prints the problems.
- With `--fix`, edits the files. It does not format them, so use `pun check --fix` for both.
- Only `error` rules fail the run. `warn` rules only report.
- Skips Blade, `vendor/`, `bootstrap/cache`, `build`, `node_modules` and `storage`.

```toml pun.toml
[lint]
sets = ["dead-code", "modernize"]

[lint.rules]
"style/require-final-class" = "error"
"types/no-loose-comparison" = { level = "warn", fix = "off" }
"style/no-short-ternary" = "off"
```

To ignore one line, add `// @pun-ignore <rule> -- <reason>`. See [ignore comments](/docs/configuration/ignore-comments).

## Exit codes

| Code | Meaning |
| --- | --- |
| 0 | No errors. |
| 1 | Errors, or too many warnings. |
| 2 | Pun could not run. |
